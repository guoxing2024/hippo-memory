## v0.2.x — recall quality & trust

- [x] **`memory_maintain duplicates` gains a `merge` action** — engine `mergeDuplicates({ ids, into?, dryRun? })`, exposed as `merge` in both adapters (preview by default, `dry_run: false` applies). A confirmed group folds into one live trace: extras are **demoted into** the survivor (same mechanism as `compress`, so `undemote` restores them and nothing reaches `memory_history`-then-delete), and the survivor first inherits the union of entities/tags plus the richest `detail` and highest `importance`. Refuses three things: rows whose premise disagrees with the survivor (returned in `blocked[]` naming the clashing key — `duplicates()` now reports per-row `scope` and a group-level `mixedPremises`), ids that are not restatements of one claim, and marker rows (`retraction` / `guard` / `invariant`). opencode gained the missing `undemote` action so the reversibility the note promises is actually reachable there.
- [x] **Digest never renders a bare top-1 as fact** — when nothing clears the floor, `composeContext` now shows the single closest trace as line 1 marked `[low-confidence sim 0.31 < floor 0.32: the closest trace, not a memory — verify before asserting]`, with `items[0].lowConfidence` for programmatic checks and a warning naming the standing. A guess never borrows `[VERIFIED]` / `[ASSERTED]` from its row. No guess at all when similarity is 0 or the store is empty; `{ lowConfidenceTop1: false }` opts out. The `[recent]` backfill on zero hits was withdrawn (it made the channel look healthy while serving the last writes) — this is the batch's one behaviour-contract change. Miss counter: `diagnostics().coverage = { turns, misses, guesses, scope: 'process' }`, deliberately not persisted.
- [x] **`status` reports `sibling_stores` and the effective scope rule** — engine exports `surveyStores(dir, { current })` (row/demoted counts and mtime per `.db` beside this one, `current` flagged, unopenable files listed in `unreadable[]` instead of losing the report) and `SCOPE_RULE` (the "memories never cross store files" contract, written once). `diagnostics()` carries both plus `suspicious.emptyWhileSiblingsFull`; each adapter adds a host-specific `path_rule` (per-agent-id vs per-project-directory) and its `health` verdict now checks the store split before the embedder mismatch. `:memory:` stores skip the directory survey.
- [x] **`verify`'s yes needs an anchor (0.3.2)** — field report D1: `verify("Python 是用来煮咖啡的")` returned `substantiated: true` at score 0.47 against a row about which language the backend uses, i.e. the verdict answered "did anything clear the *recall* floor (0.32)?" while the tool promises a claim-level answer — and 0.47 is under the `claimThreshold` (0.75) this same store publishes. Raising the floor was measured and rejected (that hallucination scores claim-to-summary 0.444; a legitimate paraphrase of the same fact scores 0.444 — the number cannot separate them). A yes now requires an **anchor**: agreeing subject with a non-clashing value, a shared identifier (ticket id / sha / version), the trace carrying the claim's wording (normalized containment or ≥ `claimThreshold` coverage of its distinctive tokens), or claim-to-summary cosine ≥ `claimThreshold`. None of them → `weak_match: true` + a `WEAK_MATCH:` note, with `support` still attached and labelled as a lead. Anchors read the **raw** stored text on purpose (`sanitizeMemoryText` can hollow a summary out to `[sanitized-conceal]friday`, erasing the very wording asked about); polarity and contradiction detection keep the sanitized text, where a payload must not get to hide. (#65 refines the value half: a filler standing as the value (`flag is on`) leaves no comparable terms, so `valueClash` stays silent — that silence is kept, unknowns still never refute — and the fourth belt downgrades the pair instead of any similarity anchor certifying it.)
- [x] **A conflicting premise vetoes even when it lost the support slot (0.3.2)** — field report D2: a `scope: env=prod` row answered `verify(…, { scope: 'env=dev' })` as `substantiated: true` with the prod row demoted into `newer_related[]`. Root cause was not a missing gate but an **unreachable** one: premise-aware ranking deliberately puts a scope-less row *above* a conflicting one, and the old veto only read `best.scope`. The comparison now scans every row that cleared the floor and `scope_conflicts[]` names the blockers. Relevance is anchored on similarity alone — entities are optional, and gating the veto on entity overlap made it inert for every entity-less store (opencode's own adapter test caught that, not reasoning). Skipped when the support already satisfies the caller's premises, so a row stated under *other* conditions cannot veto an answer found under the caller's own. **This item's own fix is what the eighth batch had to reopen** — "satisfies the caller's premises" was still `scopeDifferences(...) === 0`, and a premise on an axis the caller never named has no differences to report, so it satisfied the premise, won the slot and short-circuited the scan; see the G1 item below. **The ninth batch reopened the other half of this decision** — comparability has to be read at *every* exit that consumes "no differences", and two exits kept reading that empty as agreement; see the G3 item below it. **The eleventh batch (RR2) reopened the ranking half a third time, from the opposite direction**: the very band that lets a premise-free row answer any caller also let a premise-free row about *something else* win the seat, and the row that was the claim verbatim then vanished from all four lists — not a false yes, a **true statement demoted to no evidence**. `src/memory.ts:2869` now makes that band earn its rank with the same predicate the veto uses; see the RR2 item below.
- [x] **A Chinese copula no longer hides a value clash (0.3.2, re-test R1)** — `verify("gto 最大并发连接数是 512")` stamped `substantiated: true` (bge sim 0.81) against a row whose truth is 128, while the same claim as `-> 512`, and the English `probe-lang cache dir is E:\other-cache`, both correctly contradicted. Structural, not threshold-dependent: `claimParts` parses English copulas only, so the claim side was `null`, the value-clash branch required **both** sides parsed and was therefore unreachable for Chinese, and control fell to the cosine anchor D1 had added — i.e. the more similar the sentence, the likelier a wrong value got a stamp. Fixed in `valueFlip` with two routes that can only downgrade a verdict or name a clash: a one-sided parse (the other text must *start* with the parsed subject; the connective inherited from the other side's phrasing is stripped so a trimmed-down refinement is not read as a clash) and, when neither side parses, shared-prefix + first-number-after-it (`…设定为 30 秒` vs `…设定为 90 秒`). Deliberately **not** a Chinese copula table in `claimParts`: that parser also feeds write-side dedup and conflict detection, where a wrong split *raises* a verdict.
- [x] **The contradiction exit got the anchor too (0.3.2, re-test R2)** — any stored Chinese row containing 不 refuted every unrelated negated claim above the recall floor (`the moon is made of cheese` sim 0.46, `python is not a compiled language` sim 0.58 came back CONTRADICTED; deleting the 不 from the summary flipped it to WEAK_MATCH, which is the controlled differential). `NEGATION_RE`'s CJK arm matches a single character **and** the polarity comparison asked for no subject evidence, running before D1's anchor check. `polarityAnchored` now requires structural evidence (shared identifier / ≥4 content chars of normalized prefix / one side's parsed subject in the other text / the support row's own entity tag in the claim); `NEGATION_RE` itself is unchanged (one entry point, `polarityOf`, with 8 call sites, most of them outside verify), and an unanchored mismatch stays visible in the note as "a coincidence of negation, not a proven conflict". The gate is also `&& !polarityMismatch` on the substantiation side, or the fix would have traded a false CONTRADICTED for a false SUBSTANTIATED: `cache warmup -> warmed during startup` asked back as `during startup the cache is not warmed` covers the distinctive-token anchor 3/3 at sim 0.60 with no subject anchor anywhere, and test 22 of `test/verify-claim-gate.test.mjs` is what pins it (delete the belt alone and that is the one case that turns red).

- [ ] **What `wordFlip` still cannot see, and what it costs** — three measured gaps, and two more that round 6's quantity exemption added. (a) **Synonymy**: a one-token rewrite whose two tokens mean the same thing loses its yes (`requests`/`queries`, `drains`/`empties` → WEAK_MATCH; test 50). The positional rule has no way to know a word is *another name for* the stored value rather than a competitor to it; each such row's in-table copula twin was already CONTRADICTED before V1, so nothing that held a yes lost it, but the class is real. Round 6 moved one row **out** of it and left the rest **in**, the same single row in each space while the other 39 of 40 panel rows read identically on both builds (`.hippo/run-surface-round6.sh` → `.hippo/v2fix-surface-{hash,bge}-final.txt`): `gto gateway listens on port 8080 internally` vs `… interface 8080 …` substantiates again (0.824 hashing / 0.915 bge) because the exemption reads the number that follows the swap, while `gto gateway serves 200 requests per second` vs `… 200 queries …` still degrades — `quantityAt` looks **forward** from the divergence only, so a quantity stated *before* the slot never exempts it. Making the window bidirectional is a genuine option and it un-pins the price test 50 states on purpose, so that is a decision to take, not a patch to apply. (b) **Word order and multi-token edits**: the rule requires equal token counts with exactly one differing index, so `gto 的 max connections 是 128`-style reordering and any two-word rewrite escape it and fall back to the cosine anchor alone. (c) **Unsegmented Chinese**: `网关使用蓝色主题` vs `… 绿色 …` clears no floor at all in the hashing space (sim 0.000) and does not reach a verdict in bge either, so it is outside this mechanism entirely, not inside it and wrong — test 49 pins that reading so a later round does not "fix" it by lowering the recall floor. It needs the same CJK segmentation as the prose item above. (d) **The exemption's 12-character budget, and the word that moved eats it**: `quantityAt` matches `\D{0,12}?` **starting at the diverging word itself**, so a value word's own length counts against the budget and both sides have to reach the number for the exemption to fire. Measured by locating the edge instead of asserting it (`.hippo/probe-exemption-window.mjs` → `.hippo/exemption-window-hash.txt`, gap = leading non-digits from the divergence to the digit, computed by the probe rather than typed): `configured 30`/`capped 30` (11/7) substantiates, `capped since 30`/`held since 30` (13/11) **degrades** (`capped near 30`/`held near 30` (12/10) substantiated until #64 put `near` in the boundary set — now WEAK, safe side), and `configured near 30`/`capped near 30` (16/12) degrades even though the claim side is inside the budget — one side out is enough. So the ordinary English shape `configured at 30 seconds` vs `capped at 30 seconds` (14/10) is a legitimate rewrite that still loses its yes. The budget is short on purpose (`LEADING_QUANTITY_RE`'s comment: a number buried at the end of a long remainder is some other fact in a sentence that merely starts the same way), and **the same 14 characters also cost a refutation, not just a yes**: `… configured at 30 …` asked back as `… capped at 90 …` lands WEAK_MATCH (0.647) rather than CONTRADICTED, because `numberFlip` reaches for the number through that same window and the two predicates also differ, so this is not the dangerous direction. Raising the budget is the same trade R3 measured and needs a panel of both directions before it moves; counting from **after** the diverging word is the alternative that would fix `configured at` without touching how far past a number the rule may look. (e) **A subject swap that is followed by the same number is not vetoed**: `the primary 8080 endpoint` vs `the standby 8080 endpoint` substantiates, because the exemption asks only whether both sides then state the same number, not whether the diverging pair was itself value-shaped. ## v0.3.x — semantic memory

- [x] **`scope` field (premises, not namespaces)** — improvement proposal P0-1b. A memory can now state the conditions it holds under (`population=… ; comparator=… ; release=…`), compared structurally with **no new similarity threshold** (`diagnostics().thresholds` unchanged): only keys both sides name, values compatible when one contains the other or Jaccard ≥ 0.5. **0.3.2 (F1) removed the silent hole in that first clause** — a premise written as a bare segment names no key, so it matched nothing and could neither veto nor be honoured; bare segments now collect under an internal `@premise` key (`src/memory.ts:3969`) and pass through the same comparison, which is what makes "only keys both sides name" safe rather than blind. A write whose premise disagrees with the nearest incumbent is kept as its own trace (`different-scope:` warning) instead of overriding it; `sourceMonitor(claim, { scope })` prefers the trace stated under the caller's premises, answers `out_of_scope` on a disagreement, and appends a `CONDITIONAL SCOPE` note when the support's premise was never checked. `scope` renders as `[scope: …]` in composed context and is surfaced by `recall` / `neighbours` / `history`. Old stores gain the column through `ensureColumns()` — no migration step.
