# 🧠 HippoMemory 使用说明（完整版）

> 适用插件：**dsh-hippo-memory**（DSH 记忆插件）
> 核心引擎：hippo-memory-core
> 更新：2026-09-07

---

## 1. 这个插件解决什么问题？

DSH 的 agent 和 AI 对话一样有个毛病：**聊得太长就"忘事"**。

- 上下文窗口是有限的，几十轮之后，早期的关键结论会被挤掉；
- 一旦旧事实从上下文里消失，模型就会**凭感觉编造**（幻觉）或前后矛盾；
- 换了新会话，之前项目里定下的规矩、查清的事实，全部归零。

HippoMemory 模仿人脑的**海马体**，给 agent 装了一个"长期记忆"：
重要的东西**主动存下来**（写），需要的时候**按线索想起来**（查），开口前**核对是不是真有依据**（验），记忆还会**自动整理**（巩固/遗忘）。记忆存在本地数据库里，**跨会话、跨重启都还在**。

```
没有 HippoMemory：  长会话 → 上下文爆 → 忘事 → 幻觉
有 HippoMemory：    重要结论 → 本地记忆库 → 每轮按需唤起 → 有据才答
```

## 2. 安装

### 2.1 前提
- 已安装 DSH（DeepSeek runtime），版本 ≥ 0.1.1-rc.1
- Node.js ≥ 22.5（插件使用内置 SQLite）

### 2.2 安装命令

```bash
# 装进 web profile（图形界面那个）
dsh plugin --profile web add dsh-hippo-memory

# 如果要用在其它 profile（如 headless），换成对应名字：
# dsh plugin --profile headless add dsh-hippo-memory
```

### 2.3 重启

```bash
dsh web
```

重启后打开 **设置 → 插件 → 插件配置**，应该能看到 **"HippoMemory 记忆"** 卡片。

> 装完如果卡片没出现：确认安装命令没有报错、profile 名字正确、然后**完整退出再启动** dsh（不是只刷新页面）。

## 3. 设置（GUI 卡片）

点开"插件配置"里的 **HippoMemory 记忆** 卡片：

| 设置项 | 默认值 | 说明 |
|---|---|---|
| **启用** | 开 | 总开关。关掉后 agent 立即失去记忆工具和自动摘要（**已存的记忆不会丢**，重新打开即恢复） |
| **上下文条数上限** | 6 | 每一轮自动注入给 agent 的记忆摘要最多几条。调大 = 记得更多但更耗 token；调小 = 更省 |
| **共享存储** | 关 | 开 = profile 内**所有会话共用一个记忆库**；关 = **每个会话各记各的** |

改完点 **保存**。如果没保存就离开，卡片会提示"有未保存修改"。

### 什么时候开"共享存储"？
- ✅ 开：你有一个大项目，多个会话分工协作，希望 A 会话查到的结论 B 会话也能查到
- ❌ 关：你在同一个 profile 里混着干多个不相干的事，不想互相串味

> 注意：切换共享存储只影响**之后**的写入。之前各自会话里的记忆不会自动搬进共享库。

## 4. 它会自动做什么？

启用后，每个 agent 会话会自动获得三样东西：

1. **记忆工具**（4 个）——agent 随时可以调用：
   - `memory_remember`：写入一条记忆（带类型/来源/置信度/标签）
   - `memory_recall`：按问题检索相关记忆
   - `memory_verify`：核对"某个说法在记忆里有没有依据"
   - `memory_maintain`：整理（巩固规则 / 清理弱记忆 / 查看统计）

2. **记忆纪律**（系统提示）——agent 的"使用手册"，教它：
   > 学到持久结论 → 立刻写；涉及旧事实 → 先查再答；断言记忆内容 → 先验证；写错的被纠正 → 旧版本自动存档，不冲突覆盖。

3. **每轮自动摘要**——每轮开工前，引擎自动从记忆库里检索与当前任务**相关**的旧结论，拼成一小块 `[hippo-memory digest]` 塞进上下文，让 agent 一开局就"记得"相关背景。

```
你: 继续上次的脱壳攻坚（新会话，什么都没说）
       ↓ 引擎自动检索
[hippo-memory digest] 命中 3 条：D-284 攻坚令…、Core.dll 状态…、项目铁律…
       ↓
agent: （不用你复述）好，上次冻结在 51/8，我先从 D-284 解冻开始…
```

## 5. 手动引导 agent 用记忆

插件默认就绪，但 agent 是否"勤快"取决于它的判断。想让某个会话**认真用**，直接把下面这段话发给它：

```
【启用长期记忆】从现在起：
1. 学到持久结论、做完重要事情 → 调用 memory_remember 写入（用"<主题> -> <结论>"格式）；
2. 被问到旧事实/旧决策/项目历史 → 先 memory_recall 查，不要只凭当前对话猜；
3. 想引用"我记得"的内容 → 先 memory_verify，没依据就明说记不清；
4. 长会话定期 memory_maintain 整理一次。
每轮结束自检：这轮有没有值得长期保留的结论？
```

想要更"狠"一点，可以加一句：

```
如果我认为该写却没写，提醒我。
```

## 6. 记忆工具速查（给开发者 / 进阶用户）

工具是普通 DSH 工具，agent 会以 JSON 参数调用。你也可以在 prompt 里示范：

| 工具 | 关键参数 | 示例意图 |
|---|---|---|
| memory_remember | kind: `semantic`/`episode`/`procedure`; summary; detail; entities; tags; confidence | "记下：Core.dll 脱壳状态 -> 阻塞中（D-284 攻坚中）" |
| memory_recall | query; entities; kind; limit | "查一下之前关于 Core.dll 的结论" |
| memory_verify | claim | "核对我说的'快照重建路线已判死'有没有依据" |
| memory_maintain | action: `consolidate`/`forget`/`stats`/`history` | "整理记忆 / 看记忆统计" |

**写记忆的最佳实践**：summary 用一句话，格式 **"<主体> -> <结论>"**（例如 `billing service db -> postgres`）。这个格式能触发"纠错覆盖"机制：用户后来纠正为 mysql 时，旧记忆自动版本化存档（v1→v2），查到的永远是最新值，且 `history` 可查演变。

## 7. 数据存在哪？怎么备份/清空？

| 内容 | 位置 |
|---|---|
| 会话 A 的记忆 | `~/.dsh/storages/hippo-memory/session-<A的id>.db` |
| 共享记忆 | `~/.dsh/storages/hippo-memory/shared.db` |
| 开关与设置 | `~/.dsh/settings.yaml` 里的 `hippo-memory:` 段 |

- **备份**：复制 `storages/hippo-memory/` 整个目录即可
- **清空某个会话的记忆**：退出 dsh 后删除对应 `.db` 文件（.db-shm/.db-wal 一起删）
- **想迁移到别的机器**：带上 `storages/hippo-memory/` 目录即可，纯本地文件

## 8. 常见问题 FAQ

**Q1：装了但旧对话没有记忆？**
正常。插件只对它**装上之后**的对话生效。旧对话没经过记忆工具，不会自动补录。想让旧对话的要点进记忆，在那个对话里让 agent 用 memory_remember 补写。

**Q2：会多花很多 token 吗？**
不会。工具调用是 agent 主动触发才花钱；自动摘要只在**命中相关记忆**时注入（每条约 20–40 token），一条都不命中就是 0。条数上限可调（默认 6）。

**Q3：记忆里存了敏感信息怎么办？**
记忆全在本地 SQLite，不联网、不云同步。删除对应 `.db` 即彻底清除。也建议别让 agent 把密码等写进记忆。

**Q4：为什么 agent 有时候"不用"记忆工具？**
记忆工具的调用是模型自主决定的（和人类一样，不是每次都想到去查）。把第 5 节的引导语发给它，或在该会话的预设/系统提示里强化纪律，会有明显改善。

**Q5：查询结果不理想/verify 说查无此据？**
离线模式用的是轻量本地检索，对"换一种说法"的中文查询召回偏弱（0.32 阈值已是最佳平衡）。技巧：
- 查询里带上实体名（如 `Core.dll`、`D-284`）这类精确词；
- 用更接近当初 summary 的措辞再查一次；
- 需要强语义时，可自行给引擎接真实嵌入模型（`setEmbedder`，见 hippo-memory-core 文档）。

**Q6：停用再启用，记忆还在吗？**
在。停用只是卸掉工具，数据库原封不动。

**Q7：多个 DSH profile（web/headless）共享记忆吗？**
不共享。每个 profile 各自在 `~/.dsh/storages/` 下建库。同一个 profile 内可开"共享存储"实现会话间共享。

## 9. 卸载

```bash
dsh plugin --profile web remove dsh-hippo-memory
```

想连记忆数据一起删：删除 `~/.dsh/storages/hippo-memory/` 目录。
